# Standard Operating Procedure: Technical Text Layout and Scientific Data Audit
**Document Identifier:** SOP-MYC-042  
**Version:** 1.0.2  
**Effective Date:** November 2026  
**Review Cycle:** Annual  
**Domain Focus:** Life Sciences / Curriculum Content Quality Control  

---

## 1.0 Purpose and Scope
This Standard Operating Procedure (SOP) defines the systematic validation sequence for auditing automated scientific text strings, structural layout data, and lesson curriculum frameworks. The objective is to enforce nomenclature accuracy, visual consistency, and data integrity prior to external system deployment or student-facing instructional delivery.

---

## 2.0 Document Control and Workspace Setup
To eliminate multi-window tracking fatigue and visual data errors, auditors must establish a dual-workspace environment using G-Suite or compatible version-controlled platforms:
*   **Primary Pane:** Source compliance playbooks and multi-page evaluation rubrics.
*   **Secondary Pane:** Live spreadsheet data models (Google Sheets) or text string manifests.
*   **Validation Variable:** Prior to executing cell formatting, confirm that column constraints are locked to prevent accidental structural shifts.

---

## 3.0 Step-by-Step Verification Protocol

### Step 3.1: Nomenclature and Technical Alignment Review
1.  Isolate all biological terms, taxonomy strings, and chemical notation layouts within the target text block.
2.  Cross-reference each string against the approved domain dictionary or master project playbook.
3.  Verify that all multi-word scientific names adhere to standard formatting taxonomy (capitalized genus, lowercase species, and appropriate italicization markers).
4.  Audit structural layout breaks to ensure complex text blocks do not truncate or overlap surrounding graphic frames.

### Step 3.2: Multi-Page Rubric Scoring and Data Entry
1.  Evaluate target outputs against the structured evaluation rubric across three main vectors: tone, stakeholder fit, and compliance tracking.
2.  Log performance scores directly into the master data spreadsheet matrix.
3.  For any noted model errors or instruction-following failures, flag the string with a strict severity tag (Minor, Major, Critical).
4.  Formulate a concise, written logical rationale within the tracking cell, explicitly citing the specific section of the style guide or policy being applied.

---

## 4.0 Inter-Rater Calibration and Quality Metrics
Auditors must maintain a high inter-rater calibration score across all independent batch processing cycles. 
*   **Batch Tracking:** Run systematic sample audits in fixed sequences of 10 or 25 outputs.
*   **Error Logging:** Document all corrected typographical inconsistencies, en-dash alignments, and layout deviations.
*   **Submission Gate:** A batch cannot be marked as verified if a single data parameter contains an unresolved formatting error.
